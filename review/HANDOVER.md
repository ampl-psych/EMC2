## How the new joint translation move is switched on, and how to prove it fired

- Code: `JointMoves` in `src/sampler/runner.cpp`; R side `scale_move_stages()` and `scale_move_init()` in `R/variant_standard.R`, `create_lik_prec()` in `R/fitting.R`, `prepare_native_stage()` in `R/sampling_cpp.R`.
- **Default: on.** `options(emc.scale_move)` unset or `TRUE` runs the scale and location moves in `burn`, `adapt` and `sample` (88668e92 added burn; before it was adapt and sample). `FALSE` disables both; a character vector names the stages.
- **Type:** every hierarchical type (`standard`, `diagonal`, `blocked`, `diagonal-gamma`, `infnt_factor`, `SEM`), never `single`. Verified for standard, diagonal, diagonal-gamma, blocked (script 06).
- **The location (translation) move additionally requires no group-level design** (`make_emc(..., group_design = NULL)`): `location_ = !present(sampler, "group_designs")`. With a `group_design()` only the scale move runs (script 06). Both planned SBC cells have no group design, so the move is active in both.
- **No other setting gates it.** The directions are rebuilt from `lik_prec` at every `add_proposals()` call (every step of burn and adapt, and once when the sample kernel is tuned); when no `lik_prec` is available the directions fall back to the prior Cholesky factor, so the move still runs.
- **Evidence from a fitted object** (`emc` with at least one burn step): `sm <- attr(emc[[1]]$samples, "scale_move")`. The move ran iff `!is.null(sm$directions)` (a p x p matrix) and `sm$loc` has moved away from 1 (it restarts at 1 whenever the directions are rebuilt and adapts by `exp(.1 * (accepted - .3))` per iteration, so a value != 1 means proposals were made and accepted/rejected). `sm$uses` counts sweeps. In the sample stage `step`, `loc` and `directions` are frozen; compare them before and after a sample stage to confirm the kernel was fixed. For a definitive on/off, re-run a sample stage from the same object under `options(emc.scale_move = FALSE)` with the same seed and check the draws differ (script 02, section G). There is no acceptance log for the location move in 8b257e3d; if you want one for the SBC report, record `sm$loc` per replicate (a `loc` far below 1 means the move was being rejected, above 1 accepted).
- In SBC's per-replicate worker the objects are not kept; to record the evidence, wrap `fit` (via `dots`) or read `attr(emc[[1]]$samples, "scale_move")` inside a thin wrapper around `run_SBC_hierarchical_rep` and save `loc`/`dim(directions)` next to `rep_<i>.rds`.

## The two SBC cells

- Keep **cell 1, the vignette hierarchical LBA** (diagonal-gamma, `n_subjects = 20`, `trials = 100`) as is. One replicate is 2.1 min at 3 chains x 1 core on a 4-vCPU box (script 10): 500 replicates are about 18 three-core-hours.
- **Change cell 2** rather than running the vignette DDM unchanged. What the move does that the old one did not: it moves along dense directions mixing all parameters, with the step size set by the summed subject likelihood curvature in the *prior-whitened* metric, and the prior ratio uses the full prior precision `P` (so prior correlations, if any, and the prior scale enter the acceptance). The cases that can go wrong are therefore (i) a transformed parameter whose sampled-scale posterior is skewed or bounded (probit Z, and SZ which sits near the pnorm bound), and (ii) a correlated group covariance where the whitening and the Gibbs step interact (type `standard`). The vignette DDM covers (i) but uses diagonal-gamma, which does not test (ii). I would run cell 2 as the **vignette DDM design (v, a, t0, Z, sv, SZ, st0) with `type = "standard"`**, 20 subjects, 100 trials, prior means/sds as in the vignette and the default standard-type hyperpriors, and read its `Sigma` ranks against the 2026-09-30 archive row (the standard prior's mass near zero group variance is a known source of Sigma-rank bias that is not the move's fault; the `mu` and `alpha` ranks are the clean test of the move). If the archive precedent used diagonal-gamma for both and you need comparability over a correlated-covariance test, keep diagonal-gamma for cell 2 and add a third small cell (LNR, `type = "standard"`, 20 subjects, 100 trials; a replicate is a few minutes) for the correlated covariance.
- Cost: one DDM replicate took 52 min at 3 chains x 1 core (script 10); 500 replicates are about 430 three-core-hours, roughly 14 hours of one 96-vCPU machine at 32 replicates in parallel. That makes the DDM cell the item that sets the SBC's share of the plan, comparable to one production DDM fit.
- Sharding: `run_sbc()` runs `run_SBC_hierarchical_rep(i, ...)` for the missing replicates with `mclapply(mc.cores = cores_per_chain)` and forces `cores_per_chain = 1` inside each fit, so `cores_per_chain` is the number of replicates in flight and each fit uses `cores_for_chains` threads (3 by default). To shard across machines, draw `prior_mu`/`prior_var` once (the two `plot(prior_in, ...)` calls under a fixed seed, as in `SBC_hierarchical_parallel`), write `prior_samples.rds` into every machine's temp directory, call the worker for that machine's replicate indices, sync the `rep_<i>.rds` files, and reassemble with `recover_sbc(tempdir, design, fileName, prior_in)`; replicate i's data depend only on `prior_mu[, i]`, `prior_var[,, i]` and the worker's own RNG use, so give each worker `set.seed(<base> + i)` before the call.

## The build on gcc/libgomp (Ubuntu 24.04, gcc 13, R 4.6.1)

- A clean `R CMD INSTALL --preclean` of 8b257e3d on Ubuntu 24.04 / gcc 13.3 / R 4.3.3 works with OpenMP and `OMP_PAUSE 1` (configure probes `omp_pause_resource_all`; `inst/include/build_info.h` records it). `configure` now runs `tools/check-linalg.sh`, which compiles a tiny shared object against `$(LAPACK_LIBS) $(BLAS_LIBS) $(FLIBS)` and aborts with instructions if that fails: the machine needs `r-base-dev`/gfortran runtime, which the production AMI already has if it built earlier commits.
- `src/Makevars` and now `src/Makevars.win` are generated by configure and git-ignored; `cleanup` removes them. Build from a fresh checkout as aws/README.md says; the header-dependency lines appended to Makevars make an in-place rebuild safe too.
- Fork safety: Niek's `src/openmp.h` releases libgomp's thread pool when `native_run_chains`, `native_init_chains`, `native_lik_prec` and `calc_ll_multithreaded` return. A threaded run followed by threaded fits in `mclapply` children returned correctly here (script 04). `run_sbc()` relies on this.
- `emc2_build_info()` no longer prints the OpenMP runtime line (PR #202 added it); the log will show PNORM_MODE, flags and OMP_CXXFLAGS only. `KMP_AFFINITY` is irrelevant on a gcc build.
- Threads: `cores_for_chains x cores_per_chain` OpenMP threads, independent of `OMP_NUM_THREADS`; Ubuntu's R links OpenBLAS, which adds its own threads to the Armadillo group-level algebra, so set `OPENBLAS_NUM_THREADS=1` on the fit machines or the CPU% in the log overstates the sampler's own use (script 05 shows user/elapsed 1.7 at 1x1 on the DDM before that was set).
- The CDM/PSDM/PHSDM likelihoods run one chain and one subject at a time with no warning at 8b257e3d; none of the ConflictEAMs models is one of these.
